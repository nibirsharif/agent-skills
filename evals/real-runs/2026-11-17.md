# Real run, 17 November 2026

The whole chain run once on a real project instead of the `textstats` fixture: write-spec, write-plan, write-tasks, then build-phase on phase 1. This page records where the chain stopped or needed a person, and what became of each finding. It is the evidence for Stage 5 of the quality plan. The project is private, so it is described only as far as the findings need.

## The run

- **Project:** a private Python web backend (uv, pytest, Ruff, pyright, Alembic migrations, PostgreSQL with row-level security per tenant), whose tests need a running PostgreSQL. Its CI runs lint, format, type, and import-boundary checks besides the tests.
- **Feature:** a command that re-wraps every tenant's stored secrets under a new key-encryption key, built on the project's existing envelope-encrypted store.
- **When and with what:** 17 November 2026, `claude-sonnet-5-5`, Claude Code 2.1.327, the skills from this repository's `master` loaded with `claude --plugin-dir`. The person typed each command in one interactive session and answered every question; the build-phase reruns also ran in it, except the last, which ran in a fresh session.
- **Input:** one sentence naming the command and why: retiring a leaked or old key.
- **Result:** 29 requirements, a plan of 5 phases, 29 tasks, and phase 1 built and verified: 4 commits plus the spec commit, the test suite passing, `Verify: 4 met`. It took four build-phase runs; three stopped first.

Observations that are not failures:

- write-spec did not raise the design facts the code holds: that rotation only re-wraps the data keys, that nothing recorded which key wrapped a row, and that row-level security limits each transaction to one tenant. The person supplied them. Its questions on failure handling, reruns, reads during rotation, and writes during rotation (a real race) were good.
- write-spec asked again about a time limit the person had answered with "don't know yet", which its rules allow, since only an answer closes a question.
- write-spec wrote one sentence between its tool calls ("Q-009 and Q-010 each hold two decisions, so I'm splitting them") before its question list.
